# ADR 0011: MCP Events consumer

Date: 2026-10-05

goblin consumes the draft MCP Triggers & Events profile through the existing authorized MCP connection. Discovery
preserves the producer's top-level `capabilities.events` declaration. The client supports `events/list`, `events/subscribe`,
`events/poll` and `events/unsubscribe`; `events/stream` is unsupported. Every Events selector has an exact owner grant
(server, name and canonical JSON arguments), resident authority and the endpoint-bound OAuth connection.

Webhook deliveries use Standard Webhooks v1: `webhook-id` is the occurrence id, controls use `msg_<type>_<random>`,
`webhook-timestamp` is checked within five minutes, and the HMAC covers the raw bytes of `id.timestamp.body`. Secrets
are generated by goblin and encrypted with credential-key AAD bound to the server and subscription. The hook validates
the user route token first, persists a bounded encrypted receipt, and returns quickly; dispatch runs from a durable alarm.
Verification, gap and terminated controls have separate schemas. Replayed `(subscription, webhook-id)` rows are no-ops.

Delivery is at least once. Consumer revisions are static handler keys with independent durable acknowledgements. Payloads
are metadata and untrusted data: Telegram handlers pull authoritative inbox content, and skill handlers only invalidate a
cache generation. No webhook starts a model turn directly or grants a capability. The first consumers are Telegram (`message.received`
and `question.answered`) and MySkills updates. Mail and workspace events remain unbound for routines.

A subscription is a finite one-hour lease (five-minute floor, one-day cap), refreshed before `refreshBefore`. Pending
work is bounded at 10,000 rows or 32 MiB; pages contain at most 100 events and bodies at most 256 KiB. Disconnect and
revocation attempt unsubscribe while authority remains, then tombstone locally if cleanup cannot run. The old Telegram
doorbell remains the fallback for servers without Events until the producer cut-over is verified.

Cloudflare Workers cannot pin a resolved callback IP between DNS validation and fetch, so v1 documents trusted DNS as a
residual assumption. A hardened egress service is required for strict SSRF/DNS-pinning conformance. This ADR does not
claim exactly-once external effects or a live producer round-trip; those require the deployed mygram acceptance gate.

Amended 2026-10-09: ingress answers 410 only for the owner's own refusal (`SubscriptionRequired`, `ResidentInactive`,
`Forbidden`); any other failure of its authority check is reported and answers 503, so a transient failure no longer
ends a subscription. A subscription is invalid only when its server is `NotFound` or its grant or endpoint changed; any
other lookup failure propagates. A failed maintenance sweep is reported before it is rescheduled.
